# BeatShoot 仕様書

最終更新: 2026-09-13 / 対象バージョン: Unity 6000.3.12f1 (URP 17.3.0)

---

## 1. 概要

### 1.1 コンセプト

プレイヤーの**実際の心拍数**を計測し、それをゲーム内の照準の揺れに直結させた狙撃ゲーム。
「落ち着けば当たる／焦れば当たらない」という関係を作ることで、
プレイヤーは**自分の生理状態を制御することがそのまま攻略手段になる**。

アニメ『ソードアート・オンライン オルタナティブ ガンゲイル・オンライン』の
狙撃シーン（心拍を落ち着けて狙いを定める描写）を着想元としている。

### 1.2 狙い（脳科学賞応募の観点）

- 生体情報をゲーム入力として用い、**身体状態と操作結果の因果を可視化**する
- 発砲そのものが心拍を上げるため、**焦りが焦りを呼ぶ正のフィードバック**が発生する
- プレイヤーは呼吸や姿勢で心拍を下げようとする＝**自律神経への意識的な介入**を促す

### 1.3 中核となる体験

```
心拍が上がる  →  照準が大きく揺れる  →  弾のばらつきも広がる  →  外す
     ↑                                                            │
     └────────────  発砲・緊張で更に心拍が上がる  ←──────────────┘
```

## 4. モジュール仕様

### 4.1 HeartRateProvider

心拍数の供給元。3 つのモードを持つ。

| モード | 挙動 |
|---|---|
| `Manual` | Inspector の `bpm` をそのまま使う。調整・検証用 |
| `Simulated` | 発砲・構えで上昇し、時間で `restingBpm` へ戻る擬似心拍 |
| `External` | 外部（ウォッチ）から `SetBpm()` で与えられた値を使う |

- 出力 `Bpm` には常に Perlin ノイズによる微小変動（±1.8 BPM）を加える。
  実機の値も含めて数値が固まって見えるのを防ぐため。
- `Excitement01` = `InverseLerp(restingBpm, maxBpm, Bpm)` を公開。

### 4.2 HeartRateUdpReceiver

UDP を専用スレッドで待ち受け、受信値を `HeartRateProvider` に流し込む。

| 設計判断 | 理由 |
|---|---|
| UDP を採用 | 再送・順序保証が不要（1 秒後に次の値が来る）。ポート占有や切断でゲームが停止しない |
| 受信は別スレッド | `Receive()` がブロックするため。メインスレッドへは `lock` 経由で受け渡す |
| 指数補間（`smoothing` = 2.5） | 実機は 1Hz 更新。そのまま使うと BPM が階段状に飛び、揺れが不自然になる |
| 初回受信時に `External` へ自動切替 | ブリッジ未起動でもゲームが成立する。デモ時の事故を防ぐ |
| 8 秒無受信で `Simulated` へ復帰 | ウォッチ脱落・BLE 切断時にゲームが止まらないようにする |

### 4.3 HeartbeatAimSway（中核）

心拍から照準の揺れを生成する。**カメラの向きには一切触れない**ため、
画面は静止したまま照準マークだけが漂う（GGO の見え方）。

#### 揺れの生成モデル

照準点をバネにつながれた 2 次元の質点として扱い、力を加えて動かす。

```
加速度 = (漂う目標 − 現在位置) × springStiffness − 速度 × damping + 心拍の力
速度  += 加速度 × Δt
位置  += 速度   × Δt
```

| 項 | 内容 |
|---|---|
| 漂う目標 | Perlin ノイズ（`swaySpeed` = 0.9）× 振幅。呼吸・筋肉のふらつきに相当 |
| 心拍の力 | 心拍波形 × `heartbeatKick` × 振幅。方向は Perlin でゆっくり回転させる |
| 振幅 | `Lerp(swayCalm, swayHot, Excitement01)` |

**心拍波形**は 2 つのガウス関数の和で「ドクン、ドクン」の二峰を再現する。

```
f(p) = exp(−((p−0.10)/0.055)²) + 0.45 × exp(−((p−0.30)/0.075)²)     p: 0..1 の位相
```

> **設計上の要点**: 心拍波形を「位置」ではなく「力」として与えている。
> 位置に直接掛けると鋭いスパイクがそのまま座標に出て、拍と拍の間で動きが止まり
> カクついて見える。力として与えると 2 回積分されるため、
> 位置・速度ともに連続になり、拍の間も慣性で滑らかに流れ続ける。

#### 出力

| プロパティ | 内容 |
|---|---|
| `AimDirection` | 揺れ込みの照準方向（ワールド）。レティクルも弾道もこれを使う |
| `SpreadDegrees` | バレットサークルの半径[度] |
| `Excitement01` | 0（落ち着き）〜 1（限界） |
| `GetShotDirection()` | `AimDirection` を円内でランダムに散らした実際の弾道 |

弾のばらつきは円内一様分布（半径に `√random` を用いる）。

### 4.4 GgoReticle

円＋十字のレティクルを `OnGUI` で描画する。Canvas・画像アセットは不要。

| 要素 | 意味 |
|---|---|
| 円の**位置** | 心拍による揺れ。拍動のたびに跳ねる |
| 円の**大きさ** | バレットサークル。BPM が上がるほど広がる |
| 円の**色** | 落ち着き＝シアン → 限界＝赤 |
| 十字 | 現在の照準点 |

- 度→ピクセル変換は `Screen.height / fieldOfView` による線形近似。
  ズーム時は同じ揺れ角でも画面上で大きく見えるため、この方式で自動的に整合する。
- 円は 56 分割の線分で描画。線の太さを一定に保つため、テクスチャの拡大ではなく
  回転行列を用いた線分描画を採用している。

### 4.5 SniperShooter

| 項目 | 仕様 |
|---|---|
| 弾道の起点 | `aimSource`（カメラ）の位置。画面中央と一致させるため |
| 弾道の向き | `HeartbeatAimSway.GetShotDirection()` |
| 曳光弾の起点 | `Muzzle`（銃口）。判定と分離し、見た目の自然さを優先 |
| 最大射程 | 800m |
| 発砲時の処理 | `HeartRateProvider.AddStress(16)` で心拍を上昇させる |

外した場合も曳光弾を表示する。着弾点が見えないとばらつきが理不尽に感じられるため。

### 4.6 BulletTracer

`LineRenderer` による曳光弾。マテリアルはスクリプト内で生成し、
URP → ビルトインの順にシェーダを探索して加算合成に設定する。

- 弾速 260 m/s（実弾より遅い）。50m 先まで約 0.2 秒かけて飛び、目で追える
- 先端が明るく後端が透明なグラデーション。着弾後は筋が縮みながら消える

### 4.7 TargetScoreZones

命中点を標的のローカル座標に変換し、中心からの距離で得点を判定する。

> **設計判断**: 同心円をゾーンごとのコライダーで分けるのではなく、座標計算で判定する。
> コライダー方式では同心円の重なり順の調整が必要になるうえ、
> 小さなリングの判定が不正確になる。座標計算なら標的を回転・移動させても
> 判定がそのまま正しく動くため、**移動標的にも無改造で使える**。

### 4.8 SimplePlayerController

`CharacterController` ベース。Rigidbody は使わない。

| 機能 | 仕様 |
|---|---|
| 移動 | 歩行 4.0 m/s、しゃがみ 1.8 m/s |
| ジャンプ | 高さ 1.1m。しゃがみ中は不可 |
| しゃがみ | 高さ 1.8m → 1.0m に補間。`center` を常に高さの半分に保ち足元を固定 |
| 頭上判定 | `SphereCast` で確認。判定の一瞬だけ `CharacterController` を無効化して自己衝突を回避 |
| 視点 | プレイヤーが Y 軸、カメラが X 軸（±85°）を担当 |
| 感度 | ズーム中は FOV 比で自動的に低下（`scaleSensitivityWithZoom`） |

### 4.9 エディタ拡張

| メニュー | 内容 |
|---|---|
| `Tools > BeatShoot > シーンを自動セットアップ` | プレイヤー・カメラ・銃・的・心拍系を配置し参照を接続 |
| `Tools > BeatShoot > 射撃訓練場を作る` | 全長 120m のレンジを生成 |

- 足りないものだけを追加するため何度実行しても重複しない
- `Undo` に登録されるため Cmd+Z で一括復元可能
- セットアップはスクリプトのコンパイル後に 1 度だけ自動実行される（`InitializeOnLoadMethod`）
- 生成したマテリアルは `AssetDatabase.CreateAsset` で保存する。
  スクリプトで生成しただけのマテリアルはシーン保存時に失われるため

## 6. 得点仕様

### 6.1 配点

| 部位 | 中心 (X, Y) | 10 点 | 9 点 | 8 点 | 7 点 |
|---|---|---|---|---|---|
| 頭部 | (0, 1.335) | r ≤ 0.032 | ≤ 0.053 | ≤ 0.074 | ≤ 0.095 |
| 胸部 | (0, 0.700) | r ≤ 0.052 | ≤ 0.092 | ≤ 0.132 | ≤ 0.172 |

単位はメートル。標的ローカル座標（原点＝標的の底面中央）。

- リング外・シルエット内: **5 点**
- 背面・側面: **0 点**
- すべて Inspector から編集可能。リングは配列のため行を増やせば 6 点・5 点と拡張できる

### 6.2 距離・心拍と命中精度の関係（シミュレーション結果）

50m 先の標的における照準のズレと円の大きさ。

| BPM | 照準ズレ(平均) | 照準ズレ(大) | 円の半径 |
|---:|---:|---:|---:|
| 70 以下 | 0.0cm | 0.0cm | 5.2cm |
| 75 | 16.6cm | 32.0cm | 16.7cm |
| 80 | 33.0cm | 64.3cm | 28.2cm |
| 85 | 49.3cm | 94.4cm | 39.7cm |
| 90 | 65.5cm | 124.8cm | 51.2cm |
| 100 以上 | 98.2cm | 186.9cm | 74.2cm |

胸部リング半径は 10点=5.2cm / 9点=9.2cm / 8点=13.2cm / 7点=17.2cm。
標的の胴半幅は 28cm のため、**90 BPM を超えると標的そのものを外し始める**。

## 8. 既知の制約と今後の課題

### 8.1 制約

| 項目 | 内容 |
|---|---|
| 心拍の更新頻度 | 実機は 1Hz。補間で滑らかにしているが、心拍上昇への反応は約 1 秒遅れる |
| 心拍の精度 | 光学式 PPG は手首の密着度・動きに弱く、個体差も大きい |
| 計測の開始 | ウォッチ本体で心拍計測を開始しないと 0x2A37 に通知が流れない |
| プラットフォーム | ブリッジは macOS でのみ検証。Windows は未検証 |
| レティクル描画 | `OnGUI` のため、大量描画時のパフォーマンスは最適ではない |

### 8.2 調整が必要な点

実機の平常時心拍は **88〜90 BPM** だった。現行設定（`calmBpm` = 70, `hotBpm` = 100）では
**平常時点で既に興奮度 60% 相当**となり、常時 65cm 程度の揺れが出る。

出展時には、プレイヤーごとに座って構えたときの実測値を基準に
`calmBpm` を設定し直すのが望ましい。キャリブレーション機能の実装が有効。

### 8.3 今後の拡張案

- **キャリブレーション** — ゲーム開始時に 30 秒間計測し、その人の平常値を `calmBpm` に自動設定
- **移動標的** — `TargetScoreZones` は座標計算方式のため、標的を動かすだけで対応可能
- **心拍の可視化** — 心電図風の波形 UI を追加し、脳科学賞の観点を直接的に見せる
- **スコアの記録** — 心拍と得点の相関をプレイ後に提示し、体験を数値で振り返らせる
- **M5Stack + 指先 PPG** — 更新頻度・応答性ともに手首型より有利。本番用の代替案

## 付録: 参照した BLE 仕様

| UUID | 内容 |
|---|---|
| `0x180D` | Heart Rate Service |
| `0x2A37` | Heart Rate Measurement（notify） |
| `0x2A38` | Body Sensor Location（read） |

`0x2A37` のデータ形式: 先頭バイトの bit0 が 0 なら 8bit、1 なら 16bit リトルエンディアンで BPM。
